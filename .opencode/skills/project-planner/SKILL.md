# Project Planner

Read `../IPASS-CONTEXT.md` first when available.

## Planning method
- Confirm scope and distinguish required features from optional improvements.
- Inspect current repository progress before estimating work.
- Break features into small tasks with clear owners/layers, dependencies, acceptance criteria, and test requirements.
- Sequence foundational work first: auth/roles, schema/API contracts, core exam flow, runner isolation, grading, results, and reporting.
- Identify risks involving security, hidden tests, model reliability, and deployment.
- Keep the plan appropriate for a student capstone and avoid enterprise complexity without need.
- Track decisions and unresolved questions explicitly.
- Do not silently change grading policy, role permissions, or architecture.

Estimates are rough and must state assumptions. A task is complete only when its acceptance criteria and verification are satisfied.
